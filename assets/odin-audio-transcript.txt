Slide 1. Web Technologies: Intermediate HTML and CSS.
Hello, and welcome to this presentation about Intermediate HTML and CSS for the Web Technologies subject at Riga Nordic University. The material is based on The Odin Project, which is a free resource for learning web development. We will look at the main ideas in simple language, with examples you can connect to websites you use every day. The central idea is this: HTML gives a web page its structure, and CSS controls how that structure looks.

Slide 2. What will we learn?
There are four main areas in this presentation. First, we will look at richer HTML content, including SVG graphics and tables. Second, we will explore CSS, which lets us control text, spacing, colours, and positions. Third, we will learn about forms, which let websites collect information from users. Finally, we will compare Flexbox and Grid, two important tools for arranging content. You do not need to memorize every property today. The goal is to understand what each tool does and when it may be useful.

Slide 3. HTML gives structure; CSS gives appearance.
Imagine building a house. HTML is like the rooms, walls, doors, and windows. It describes what is on the page: a heading, a paragraph, a button, or a form. CSS is like the paint, decoration, and spacing. It controls things such as colour, font size, borders, and alignment. For example, HTML can create a heading that says, Welcome. CSS can make that heading blue and larger. The browser reads both and displays the final page. Keeping structure and appearance separate makes a website easier to understand and maintain.

Slide 4. SVG: images that stay sharp.
SVG stands for Scalable Vector Graphics. It is a way to describe an image using shapes and drawing instructions, rather than a fixed grid of pixels. That makes SVG especially useful for logos, icons, simple diagrams, and illustrations. When you enlarge an SVG, its edges can remain sharp instead of becoming blurry. The example on this slide draws a circle by specifying its position, size, and colour. For detailed photographs, a format such as JPEG or WebP is usually more appropriate. So, remember: SVG is excellent for many clean graphics, while photo formats are better for complex real-world images.

Slide 5. HTML tables: organize information.
An HTML table is useful when information needs to be compared in rows and columns. Think of a class timetable: each row could represent a day, and the columns could show the time and topic. In HTML, a table element creates the table. A table row creates one row. A table header cell identifies a column or row, while a regular data cell contains the information. Meaningful headers are important because they help people understand the data, including people who use screen readers. One important rule: tables are for tabular information, not for arranging the whole design of a webpage. Modern page layouts are better handled with CSS Flexbox or Grid.

Slide 6. CSS foundations: units, text, and spacing.
A few CSS foundations can make a page easier to read and more adaptable. Browsers have default styles, so headings, buttons, and form fields already have some appearance. Developers sometimes use a reset or normalization stylesheet to make those defaults more consistent. CSS units describe sizes. Pixels are a fixed unit in common use. Rem is based on the root text size, and percentages depend on a parent or another relevant measurement. For text, font size changes how large the letters are, font weight controls how bold they look, line height controls space between lines, and text align controls alignment. Finally, margin is space outside an element's border, while padding is space inside the border. A good amount of spacing makes a page feel calm and readable.

Slide 7. CSS selectors: choose what to style.
A selector tells CSS which HTML elements should receive a style. An element selector, such as the letter p, selects all paragraph elements. A class selector begins with a dot and selects elements that have that class. Classes are useful because the same style can be reused in several places. A pseudo-class describes a state. For example, hover applies a style when a user points a mouse at a button. An attribute selector can target a specific kind of input, such as an email field. As a beginner, start with element selectors and classes. Use IDs for unique elements when appropriate, and only add more complex selectors when you really need them.

Slide 8. Positioning: where an element sits.
CSS positioning controls where an element appears. The default is static positioning, which follows the normal flow of the page. Relative positioning lets you adjust an element from its usual position, while its original space remains reserved. Absolute positioning takes an element out of normal flow and usually places it relative to a positioned ancestor. Fixed positioning keeps an element in the same place on the screen as the user scrolls, which can be useful for a floating control. Sticky positioning behaves normally until the page reaches a scroll point, then it sticks in place. These options solve specific problems, but do not use them as the first choice for every layout. Flexbox and Grid are usually easier for arranging the main page structure.

Slide 9. CSS functions and custom properties.
Custom properties are variables that store reusable CSS values. They often hold colours, spacing, or other design choices. In the example, the brand colour is saved once and then reused wherever that variable is needed. If the colour changes later, you can update it in one place. CSS also has helpful functions. Calc lets you calculate a value using different measurements. Min and max select a smaller or larger value from the options you provide. Clamp sets a lower limit, a preferred size, and an upper limit. This can be useful for responsive text, because the size can adapt to the screen while staying within sensible boundaries. These tools reduce repeated values and help a design adapt to different screen sizes.

Slide 10. Forms: collect information clearly.
Forms allow users to send information to a website. Common examples include sign-up forms, contact forms, and search boxes. A well-made form includes a clear label for every input, an appropriate input type, and a button to submit the information. In this example, the email field uses the email input type, and the required attribute tells the browser that the field must be filled in before a normal submission can continue. This is a basic form of validation and can help users correct simple mistakes. It is not a replacement for server-side validation, because a real website also needs to check submitted data on the server. Clear labels and helpful error messages make forms easier for everyone to use.

Slide 11. Flexbox versus Grid.
Flexbox and Grid both arrange content, but they are suited to different kinds of layout. Flexbox is mainly one-dimensional. That means it arranges items in a row or in a column. It is a good choice for a navigation menu, a line of buttons, or a toolbar. Grid is two-dimensional. It can organize items into rows and columns at the same time, which is useful for image galleries, dashboards, and page sections. A simple memory trick is: use Flexbox when you are arranging items in one direction, and consider Grid when you need a structured set of rows and columns. They can also work together on the same page.

Slide 12. CSS Grid: build rows and columns.
Let's look a little more closely at Grid. First, you make an element a grid container by setting its display property to grid. Then you define the columns. In the example, repeat three, one fraction unit means create three columns that share the available space equally. The fraction unit divides the remaining space into portions. The gap property adds spacing between grid items. After the container is set up, the browser places the child elements into grid cells in order. This is useful for a dashboard with cards such as visitors, orders, tasks, reports, messages, and settings. Later, you can change the number of columns for smaller screens, helping the page remain usable on a phone.

Slide 13. Three extra tools you will hear about.
As you learn more web development, you will hear about browser compatibility, CSS frameworks, and CSS preprocessors. Browser compatibility means checking whether a feature works across browsers and screen sizes. Developers should test important pages rather than assuming every browser behaves exactly the same. CSS frameworks provide reusable styles or ready-made patterns, which can make common layouts faster to build. Bootstrap and Tailwind CSS are two examples, but they have different approaches. A CSS preprocessor, such as Sass, adds features that are then compiled into ordinary CSS that browsers can understand. These tools can be helpful, but beginners should first understand standard HTML and CSS. Once the basics are clear, it becomes easier to know when an extra tool will solve a real problem.

Slide 14. Mini project: design a sign-up page.
A small project helps connect these ideas. Imagine building a simple account sign-up page. First, write the HTML structure and add labels for the name, email, and password fields, along with a submit button. Second, choose appropriate input types and mark required fields so the browser can provide basic validation. Third, use CSS to choose colours, fonts, borders, padding, and spacing. Also make the focus state visible so people can tell which field they are using. Fourth, make the page responsive. Flexbox or Grid can help arrange the form, and you should test it at a narrow mobile width as well as on a larger screen. Before calling the project complete, check that every field has a label, the validation works, spacing is consistent, and the form remains easy to use on a phone.

Slide 15. Key takeaways and quick check.
Let's review the key ideas. HTML describes the meaning and structure of content. CSS controls its appearance and layout. Forms should use labels and validation to guide users. Flexbox is generally best for arranging items in one direction, while Grid is designed to handle rows and columns together. Now, test your understanding. Question one: which is normally better for a realistic photograph, SVG or a photo format? The answer is a photo format. Question two: which layout tool is designed for rows and columns together? The answer is Grid. Question three: what does the required attribute do in a form? It tells the browser that the field must be completed before a normal form submission can proceed. If you can explain these ideas in your own words, you have understood the main points.
